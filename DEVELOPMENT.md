# Airfrog Development

Airfrog's schematics and JLCPCB files are generated by the scripts in `scripts/`. It is recommended to change the scripts, not the generated files in KiCad, because regenerating overwrites KiCad edits. Both PCBs are routed by hand.

There are two variants from one set of scripts:

| Variant | Module | Board |
| --- | --- | --- |
| `mini` | ESP32-C3-MINI-1 | 18.0 x 26.02 mm |
| `pro` | ESP32-S3-MINI-1 | 18.39 x 30.25 mm |

On both, the module's antenna overhangs the end of the board.

## Setup

Supported on macOS and Linux.

Install:

- [KiCad 9](https://www.kicad.org/download/)
- Python 3 and Git
- Poppler, for the PNG renders (`brew install poppler` on macOS, `poppler-utils` on Linux)
- Pillow, for cropping the 3D renders (`pip3 install pillow`)

The scripts use KiCad's default install, and `kicad-cli` from the PATH if it's present. If your KiCad is elsewhere, set these environment variables:

| Variable | Path |
| --- | --- |
| `KICAD_CLI` | `kicad-cli` |
| `KICAD_PYTHON` | Python with KiCad's `pcbnew` module |
| `KICAD9_SYMBOL_DIR` | KiCad's stock symbol libraries |
| `KICAD9_FOOTPRINT_DIR` | KiCad's stock footprint libraries |

`scripts/kicad-python` runs a script using KiCad's Python.

## Generating

```bash
scripts/generate.sh
```

This writes, for each variant:

- the KiCad project and a schematic PDF to `kicad/mini/` and `kicad/pro/`
- the JLCPCB files to `jlc/mini/` and `jlc/pro/`

It stops if there are uncommitted changes or untracked files.

Each board's project settings, including its ERC exclusions and design rules, are in its project file in `pcb/mini/` or `pcb/pro/`. `check.sh` runs ERC with the settings in `kicad-src/airfrog.kicad_pro`.

## Changing the Schematic

The schematic is generated by `scripts/airfrog.py`, with the variant as its first argument. Each variant's module and the module pin of each signal are in `VARIANTS` at the top of the script. After changing the script, check the schematics:

```bash
scripts/check.sh build
```

This generates each variant's schematic in `build/mini/` and `build/pro/`, runs ERC and compares the netlist with `scripts/expected_nets.py`. It prints any netlist differences and ERC violations, and a `LAYOUT` line for overlapping symbols or text and for wires that cross them. Each sheet is rendered to `sheet-1.png` in its variant's folder at 100 dpi, or at `DPI` if set. To check one variant, set `VARIANTS`, for example `VARIANTS=mini scripts/check.sh build`.

`expected_nets.py` is the netlist written by hand from the design, separately from `airfrog.py`. Update it when you change a connection, so a mistake in `airfrog.py` appears as a netlist difference.

To see part of a sheet close up:

```bash
scripts/crop.sh build/mini regulator 4 39 44 64
```

This writes `build/mini/regulator.png` at 220 dpi, from x0 y0 to x1 y1 in units of 2.54 mm from the sheet's top left.

## Changing the PCB

Each board is routed by hand, in its KiCad project in `pcb/mini/` or `pcb/pro/`. Only the board and the project file are committed. Before opening a project, and after changing the schematic, write the schematic, libraries and 3D models into its folder:

```bash
scripts/pcb_project.sh mini
```

Then bring any schematic change into the board with Tools → Update PCB from Schematic.

Both boards have 4 layers, with the parts on the top layer. In1 is a GND plane and In2 a 3V3 plane. The tracks are on the top and bottom, with GND pours filling the rest. The stackup is JLC04161H-7628 and the design rules are JLC's 4-layer limits. Copper is at least 0.4 mm from the board edge, so the boards can be V-cut in a panel.

Check the boards:

```bash
scripts/check_pcb.sh build
```

This copies each board, with its generated schematic, to `build/mini/` and `build/pro/`. It runs DRC with schematic parity and prints the violations, unconnected items and parity problems. Footprints differing from their library copies are expected, because the boards' footprints have their own silkscreen and J2 has smaller pads and courtyard. It renders each board at 300 dpi or at `DPI` if set:

- the top layers to `top.png`
- the In2 layer to `in2.png`
- the bottom layers to `bottom.png`
- 3D views from above and below to `3d-top.png` and `3d-bottom.png`

To see part of a render close up:

```bash
scripts/crop_pcb.sh build/mini top 0 0 18 15
```

This writes `build/mini/top-crop.png` at 1200 dpi, or at `DPI` if set, from x0 y0 to x1 y1 in mm from the board's top left. The second argument is `top`, `in2` or `bottom`.

The 3D renders use their own KiCad settings in `build/kicad-config/`, which show through-hole parts whatever your own 3D viewer settings are.

When a board changes, update the board renders in `images/` after running `generate.sh`:

```bash
scripts/render.sh
```

## Silkscreen

The bottom has J2's pin names, the name, the version, the commit and the copyright. Under the name is the board's own name, mini or pro, in the same font and size.

The name is in Bauhaus 93, the font of the name on the earlier Airfrog boards, drawn as filled shapes so that KiCad, JLC and anyone building the board don't need the font. The shapes come from `kicad-src/bauhaus93.json`, which `scripts/glyphs.py` writes from the font for the characters listed. To add characters, run it with a copy of the font, for example the one Microsoft Office installs:

```bash
python3 scripts/glyphs.py "/Applications/Microsoft Word.app/Contents/Resources/DFonts/Bauhaus93.ttf" airfrogmnpv0123456789. kicad-src/bauhaus93.json
```

To draw a word onto a board's underside, close the board in KiCad and give its centre and baseline in mm from the board's top left, and the height in mm if not 2.6:

```bash
scripts/kicad-python scripts/glyphs.py draw pcb/pro/airfrog-pro.kicad_pcb pro 9.79 20.9
```

The version, commit and copyright are in KiCad's font.

The [LICENSE](LICENSE) and [NOTICE](NOTICE) require "piers.rocks", in the copyright line, remain on the PCB.

## Version and Commit

The version in `VERSION` is printed in the schematic's title block. On each board's silkscreen the version is ordinary text, changed by hand.

`generate.sh` sets the commit on the silkscreen to the short hash of HEAD.

## JLCPCB Files

`generate.sh` runs `scripts/jlc.py` for each variant. It writes the zipped Gerbers and drill files, and two sets of BOM and CPL, to `jlc/mini/` and `jlc/pro/`:

| File | Contents | Assembly |
| --- | --- | --- |
| `airfrog-mini-gerbers.zip` | Gerbers and drill files | – |
| `airfrog-mini-bom.csv`, `airfrog-mini-cpl.csv` | The top-side parts | Single-sided, with J1 fitted by hand |
| `airfrog-mini-socket-bom.csv`, `airfrog-mini-socket-cpl.csv` | The top-side parts and J1, the One ROM socket, on the bottom | Double-sided |

The Pro's files are the same with `pro` in place of `mini`.

DNP parts aren't in the BOM or CPL. `jlc.py` prints `NOLCSC` for any BOM row without an LCSC part number.

If a part is rotated or shifted in JLC's preview, add a correction for its LCSC part number to `CORRECTIONS` in `scripts/jlc.py`.

## Validation

```bash
scripts/check_all.sh build
```

This runs the schematic and board checks for both variants. CI runs it on every push with KiCad 9.0.7.

## Releasing

1. Set the version in `VERSION` and on both boards' silkscreen.
2. Date the version's section in `CHANGELOG.md`, for example `## v0.2.0 - 2026-10-28`.
3. Commit.
4. Tag the commit with the version and push the tag.

The Release workflow creates a GitHub release with the changelog section as its notes. `scripts/release.sh v0.2.0` writes the same files to `build/release/`. For each variant they are:

- `airfrog-mini-gerbers.zip`, with the tag's commit on the silkscreen
- `airfrog-mini-bom.csv` and `airfrog-mini-cpl.csv`
- `airfrog-mini-socket-bom.csv` and `airfrog-mini-socket-cpl.csv`
- `airfrog-mini-schematic.pdf`
- `airfrog-mini-kicad.zip`, the KiCad project with LICENSE and NOTICE

## Parts

Each passive's footprint, LCSC part number and MPN are set by value in `PASSIVES` in `scripts/airfrog.py`. A second source's LCSC part number goes in `ALTS` and appears in the schematic's `LCSC alt` field. The ESP32-C3-MINI-1's second source is in its `LCSC alt` field.

The ESP32-C3-MINI-1 and XL-1010RGBC-WS2812B symbols are in `kicad-src/airfrog.kicad_sym`, and the XL-1010RGBC-WS2812B footprint is in `kicad-src/airfrog.pretty/`. All other symbols and footprints come from KiCad's stock libraries. The C3-MINI-1 uses KiCad's ESP32-C6-MINI-1 footprint and the S3-MINI-1 its ESP32-S2-MINI-1 footprint, which match Espressif's land patterns for those modules. KiCad has no 3D model of either module, so `kicad-src/airfrog.3dshapes/` has boxes of their size. It also has the LEDs' models, which `scripts/led_models.py` writes: the RGB LED, which KiCad has no model of, and the blue LED, whose KiCad model is uncoloured. If the schematic needs a new stock symbol library, add it to `kicad-src/sym-lib-table` or ERC fails.
