# Airfrog Development

Airfrog's schematic, PCB and JLCPCB files are generated by the scripts in `scripts/`. It is recommended to change the scripts, not the files in KiCad, because regenerating overwrites KiCad edits.

There are two variants from one set of scripts:

| Variant | Module | Board |
| --- | --- | --- |
| `c3` | ESP32-C3-MINI-1 | 18.0 x 26.02 mm |
| `s3` | ESP32-S3-MINI-1 | 18.39 x 30.25 mm |

On both, the module's antenna overhangs the end of the board.

## Setup

Supported on macOS and Linux.

Install:

- [KiCad 9](https://www.kicad.org/download/)
- Python 3 and Git
- Poppler, for the PNG renders (`brew install poppler` on macOS, `poppler-utils` on Linux)
- Pillow, for cropping the 3D renders (`pip3 install pillow`)

The scripts use KiCad's default install, and `kicad-cli` from the PATH if it's present. If your KiCad is elsewhere, set these environment variables:

| Variable | Path |
| --- | --- |
| `KICAD_CLI` | `kicad-cli` |
| `KICAD_PYTHON` | Python with KiCad's `pcbnew` module |
| `KICAD9_SYMBOL_DIR` | KiCad's stock symbol libraries |
| `KICAD9_FOOTPRINT_DIR` | KiCad's stock footprint libraries |

`scripts/kicad-python` runs a script using KiCad's Python.

## Generating

```bash
scripts/generate.sh
```

This writes, for each variant:

- the KiCad project and a schematic PDF to `kicad/c3/` and `kicad/s3/`
- the JLCPCB files to `jlc/c3/` and `jlc/s3/`

It stops if there are uncommitted changes or untracked files. It takes about 6 minutes, most of it routing.

Change ERC exclusions and other project settings in `kicad-src/airfrog.kicad_pro`.

## Changing the Schematic

The schematic is generated by `scripts/airfrog.py`, with the variant as its first argument. Each variant's module and the module pin of each signal are in `VARIANTS` at the top of the script. After changing the script, check the schematics:

```bash
scripts/check.sh build
```

This generates each variant's schematic in `build/c3/` and `build/s3/`, runs ERC and compares the netlist with `scripts/expected_nets.py`. It prints any netlist differences and ERC violations, and a `LAYOUT` line for overlapping symbols or text and for wires that cross them. Each sheet is rendered to `sheet-1.png` in its variant's folder at 100 dpi, or at `DPI` if set. To check one variant, set `VARIANTS`, for example `VARIANTS=c3 scripts/check.sh build`.

`expected_nets.py` is the netlist written by hand from the design, separately from `airfrog.py`. Update it when you change a connection, so a mistake in `airfrog.py` appears as a netlist difference.

To see part of a sheet close up:

```bash
scripts/crop.sh build/c3 regulator 4 39 44 64
```

This writes `build/c3/regulator.png` at 220 dpi, from x0 y0 to x1 y1 in units of 2.54 mm from the sheet's top left.

## Changing the PCB

The board is generated by `scripts/airfrog_pcb.py`, with the variant as its first argument. The board size, the module's position and each part's position are parameters at the top of the script. Most of the S3's parts are the C3's, moved 0.195 mm right to stay centred under the One ROM header on its wider board.

The board has 4 layers. The top has the parts and short tracks. In1 is a GND plane. In2 and the bottom have the longer tracks, with GND pours filling the rest. The stackup is JLC04161H-7628 and the design rules are JLC's 4-layer limits. Copper is at least 0.4 mm from the board edge, so the boards can be V-cut in a panel.

The tracks are routed by `scripts/router.py`, a grid router that always produces the same routes from the same input. It routes every net except GND. Then, until no two nets are too close, it reroutes the nets in conflict, making the cells they share cost more each round. Before routing, each top-side GND pad gets a via to the planes, or a track to a GND via beside it, where one fits. After routing, GND vias are added to join every piece of each pour to In1. The +3V3 supply from the regulator to the module, and its decoupling capacitors, are a 0.5 mm trunk set by `TRUNK_3V3`. SEL_A and SEL_B, from J1 to R7 and R8 and on to a via each, are drawn by `hand_routes`, and the router routes on from the vias.

It routes the same way for any commit: the via keepout round the commit text on the silkscreen is sized for any 7-character hash.

The router keeps:

- vias at least 0.1 mm from every pad, of any net
- vias out of the board's silkscreen text and the name
- tracks out of the antenna area, on every layer
- top-layer tracks under the module to short escapes from its pads
- tracks into round pads to their centre, so they meet the pad edge square on

Footprint silkscreen lines that cross a via are cut back around it.

Check the board:

```bash
scripts/check_pcb.sh build
```

This generates the schematic and board for each variant in `build/c3/` and `build/s3/`, runs DRC with schematic parity and prints the violations, unconnected items and parity problems. Footprints differing from their library copies are expected, because the generator changes their silkscreen and J2's pads and courtyard. It renders each variant at 300 dpi or at `DPI` if set:

- the top layers to `top.png`
- the In2 layer to `in2.png`
- the bottom layers to `bottom.png`
- 3D views from above and below to `3d-top.png` and `3d-bottom.png`

Generating the board also prints:

- `ROUND` lines with the number of nets in conflict after each routing round
- `UNROUTED` for any net the router couldn't route
- `STITCH` with the number of GND vias placed
- `ANGLE` for a track segment that isn't horizontal, vertical or at 45°
- `ACUTE` for a track bend sharper than 90°
- `SILK` for a part with silkscreen outside the board outline, and with the number of footprint silkscreen lines cut at vias
- `VIAPAD` for a via that overlaps a pad
- `UNPLACED` for any part without a position

To see part of a render close up:

```bash
scripts/crop_pcb.sh build/c3 top 0 0 18 15
```

This writes `build/c3/top-crop.png` at 1200 dpi, or at `DPI` if set, from x0 y0 to x1 y1 in mm from the board's top left. The second argument is `top`, `in2` or `bottom`.

The 3D renders use their own KiCad settings in `build/kicad-config/`, which show through-hole parts whatever your own 3D viewer settings are.

When the board changes, update the board renders in `images/` after running `generate.sh`:

```bash
scripts/render.sh
```

## Silkscreen

The bottom has J2's pin names, the name, the version, the commit and the copyright.

The name is in Bauhaus 93, the font of the name on the earlier Airfrog boards, drawn as filled shapes so that KiCad, JLC and anyone building the board don't need the font. The shapes come from `kicad-src/bauhaus93.json`, which `scripts/glyphs.py` writes from the font for the characters listed. To add characters, run it with a copy of the font, for example the one Microsoft Office installs:

```bash
python3 scripts/glyphs.py "/Applications/Microsoft Word.app/Contents/Resources/DFonts/Bauhaus93.ttf" airfrogv0123456789. kicad-src/bauhaus93.json
```

The version, commit and copyright are in KiCad's font.

piers.rocks in the copyright line is `COPYRIGHT` in `scripts/airfrog_pcb.py`. The [LICENSE](LICENSE) and [NOTICE](NOTICE) require "piers.rocks" remain on the PCB.

## Version and Commit

The version in `VERSION` is printed in the schematic's title block and on the silkscreen.

`generate.sh` sets the commit on the silkscreen to the short hash of HEAD.

## JLCPCB Files

`generate.sh` runs `scripts/jlc.py` for each variant. It writes the zipped Gerbers and drill files, and two sets of BOM and CPL, to `jlc/c3/` and `jlc/s3/`:

| File | Contents | Assembly |
| --- | --- | --- |
| `airfrog-c3-gerbers.zip` | Gerbers and drill files | – |
| `airfrog-c3-bom.csv`, `airfrog-c3-cpl.csv` | The top-side parts | Single-sided, with J1 fitted by hand |
| `airfrog-c3-socket-bom.csv`, `airfrog-c3-socket-cpl.csv` | The top-side parts and J1, the One ROM socket, on the bottom | Double-sided |

The S3's files are the same with `s3` in place of `c3`.

DNP parts aren't in the BOM or CPL. `jlc.py` prints `NOLCSC` for any BOM row without an LCSC part number.

If a part is rotated or shifted in JLC's preview, add a correction for its LCSC part number to `CORRECTIONS` in `scripts/jlc.py`.

## Validation

```bash
scripts/check_all.sh build
```

This runs the schematic and board checks for both variants. CI runs it on every push with KiCad 9.0.7.

## Releasing

1. Set the version in `VERSION`.
2. Date the version's section in `CHANGELOG.md`, for example `## v0.2.0 - 2026-10-28`.
3. Commit.
4. Tag the commit with the version and push the tag.

The Release workflow creates a GitHub release with the changelog section as its notes. `scripts/release.sh v0.2.0` writes the same files to `build/release/`. For each variant they are:

- `airfrog-c3-gerbers.zip`, with the tag's commit on the silkscreen
- `airfrog-c3-bom.csv` and `airfrog-c3-cpl.csv`
- `airfrog-c3-socket-bom.csv` and `airfrog-c3-socket-cpl.csv`
- `airfrog-c3-schematic.pdf`
- `airfrog-c3-kicad.zip`, the KiCad project with LICENSE and NOTICE

## Parts

Each passive's footprint, LCSC part number and MPN are set by value in `PASSIVES` in `scripts/airfrog.py`. A second source's LCSC part number goes in `ALTS` and appears in the schematic's `LCSC alt` field. The C3 module's second source is in its `LCSC alt` field.

The ESP32-C3-MINI-1 symbol is in `kicad-src/airfrog.kicad_sym`. All other symbols and all footprints come from KiCad's stock libraries. The C3-MINI-1 uses KiCad's ESP32-C6-MINI-1 footprint and the S3-MINI-1 its ESP32-S2-MINI-1 footprint, which match Espressif's land patterns for those modules. KiCad has no 3D model of either module, so `kicad-src/airfrog.3dshapes/` has boxes of their size. If the schematic needs a new stock symbol library, add it to `kicad-src/sym-lib-table` or ERC fails.
